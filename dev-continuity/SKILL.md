# 开发连续性

目的：压缩、中断或换对话后仍能完成原目标，保留决定、理由及已做事项。完整性优先，其次减少维护和读取。长开发任务使用；普通一步改动直接完成。项目事实隔离，遵守 writer/routing。

优先在原对话压缩恢复。检查点补充可追溯的项目状态，Codex 本地记忆辅助查稳定偏好、经验和历史入口；其生成可能滞后。模型升级、更大名义窗口和更高推理强度不替代原文或当前证据。宿主已有目标/进度功能时复用，启用遵守其授权，不另建续跑调度器。

## 恢复与更新

恢复执行 scripts/continuity.py recall，固定 revision 读完当前关键项，核对完整目标、批次、决定及理由、验证边界、禁止事项、未完成操作和 next。同 revision 不重复加载；跨压缩不假定旧阅读仍在上下文。按模块用 recall --query，旧决定用 --history --query，record --id 查记录，--source-index N 取一个已核对非敏感原文片段。

提出“规则未定”“用户未做”“需要重新确认”之前，先查相关当前记录、权威文档及必要原文；已决定事项沿用，缺依据说未核实。外部操作前用 operation --id 查当前与历史；未找到不授予权限。历史来源可读只证明当时原文，冲突查较新用户指示与当前现场。

重要要求/纠正、技术取舍、完成/失败、阻塞或 next 变化后及时 save --patch，不等交接；中断后在下一安全节点补齐，无实质变化不重存。保留源码无法解释的理由、限制和失败条件，普通实现细节引用代码。不复制工具输出或压缩上一份摘要代替原文。用户报告、文件、运行加载、真实端到端分别记录，推测保持未核实。

一个事实一处完整记录，其余引用 ID/路径。同步核对 goal/progress/decisions/evidence/next，移走旧“未构建”等过时现状，历史留存。日常保存不为 memory_review 再跑一轮保存/复核；整套迁移复核只在真正交接时完成，verify 用于必要审计或定位问题。

## 完整目标与有限当前记录

复用现有权威需求/验收表，goal 保留完整目标与入口，batch.scope 引用本批条目，不另建需求台账。每项要求有完成及验证范围、待做、阻塞或用户明确取消/后置的状态。来源变化、批次结束、宣称目标完成前核对全表与用户纠正，同版本有效证据可复用。批次完成不等于 completed=true。

只保留六类记忆：目标/未完成需求、用户决定/纠正、技术取舍/理由、完成/验证边界、失败/未解问题、当前现场/下一步。critical 表示本次恢复必读，包含完整需求入口、权限、禁止、未知操作和验收边界；模块细节及完成历史按需读。未确定结果与不可重复操作始终保留。

同 scope 重复要求核对原意后用 supersedes 归并，保留全部有效约束和原文；用户要求/决定不能直接退役。版本现状用 status_key，结论适用版本用 depends_on，临时观察用 validation/valid_until，到期核实，不能自动删除限制或推定授权。失败经验保留适用条件和重试前提。

短入口仅留当前状态与权威链接，发布流水放既有历史。笔记超过80%整理，超过95%禁止新交接，不能截断约束或把字节当 token。全部记录均关键时检查完成证据和临时状态。可变来源用 --retain-sources 保留已核非敏感片段，不保存聊天全集；哈希通过不证明语义完整或现状有效。

归档先落盘再发布入口；未知/在途和未执行操作保持当前。已核实结束且退出当前待办的 FAILED 可显式 retire_operations，保存理由、回执摘要和原 ID；不要改成成功、删掉失败或把 retry 压成含糊的“查”。历史 ID 不复用，锁冲突不擅删，失败保留上一检查点。

首次登记、归并、归档或来源保护读[记忆格式](references/memory.md)；保存、接棒和成本命令读[操作参考](references/operations.md)。Python 3.11+ 标准库；Windows 用 py -3 -X utf8。不直接改 Codex 生成记忆，不因本 Skill 自动更新长期规则，遵守用户授权及宿主权限。

## 持续与必要交接

按当前已授权有限批次推进，batch 写范围和完成条件，next 对应其缺口。有独立且已授权下一步就继续；人工、费用、新业务决定只暂停依赖动作。用户停止优先，完整目标达成才保存 completed=true，不自行新增目标或无限寻找缺陷。

70%提示及时保存；80%、新压缩和批次切换提示下一安全节点核对记忆，均不要求新建对话。能完整恢复就原对话继续，缺信息先补检索。仅用户要求迁移、宿主不能可靠续跑，或反复遗漏/错误重放等具体恢复问题且迁移确有帮助时评估接棒；换对话不能修复缺失原文或错误检查点。

确需迁移才检查实际工具与既有预约，记录 migrate/defer/unavailable、理由和复核节点，满足授权与安全条件后执行一次。原对话恢复正常时，不为每次压缩或同批次小步骤重写迁移声明；旧 defer 不覆盖新故障或新指示。工具未变化不反复搜索。

usage --project/--task/--session 跟随当前日志；unknown 不是余量充足或迁移理由，不猜比例，不用 API 名义窗口推定客户端容量。压缩先发生则恢复继续。必要交接仍按预约一次 → 记录真实新任务 → 释放旧写入权 → 接棒执行 next；未知结果先查，不重复创建或并发写入。用户暂不接棒、目标完成或无独立 next 时不创建；新任务先取得实质进展。

接续默认继承当前 owner 最近同一条实际 turn_context 的 model/effort，prepare 冻结后才传给 create_thread，不用旧笔记设置。有用户依据的主动调整用 for_session 绑定来源 owner，接棒后不再固定后续设置。新 policy4 在 accept 前核验接棒方真实模型/强度；不符或未知保持只读，纠正后重试同一预约，禁止另建任务绕过。旧预约保留原策略，显式默认不假报匹配；脚本不改宿主设置或自动替换不支持选项。

Hooks 只低频记录状态和短提示，不生成摘要、增加模型调用、轮询或强制 Stop 续跑。能力缺失保留短交接正文，不伪造接棒或承诺应用退出后继续。评价看遗漏、重复操作、恢复后的业务进展与维护开销，实测和模拟分开；cost 的缓存/非缓存输入、输出仅为观测，字节和累计用量不能证明净节省。
